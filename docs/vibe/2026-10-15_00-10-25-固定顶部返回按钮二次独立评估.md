# 固定顶部返回按钮二次独立评估

## 独立结论

对最新的最小方案进行第二次静态核对后，结论为：**修正一个显示条件后可以通过，用户操作闭环，不会新增明显卡顿或永久卡住点。**

需要修正的条件是：顶部返回按钮不能简单按 `folder.isNotEmpty` 显示，必须限定为：

`tab == 1 || tab == 2 || (tab == 0 && folder.isNotEmpty)`

原因是用户从子文件夹进入设置页时，`folder` 不会清空。如果仅判断 `folder.isNotEmpty`，设置页顶部会出现一个新增返回按钮，页面内容区还保留原有“返回课程库”按钮，形成重复入口。原优化方案文档已经同步修正该条件。

除这一点外，最新方案不需要增加手势、路由、系统返回拦截、等待状态或导航锁。

## 用户操作闭环

### 文件夹主流程

`课程库根目录 → 打开文件夹 → 滚动到任意位置 → 点击固定顶部返回 → 返回父目录/根目录`

- 返回按钮不属于滚动内容，不会随文件列表移出屏幕；
- 一级文件夹返回根目录；
- 多级文件夹每点击一次返回一级；
- 返回使用当前已有的同步 `setState` 逻辑，不依赖扫描、导入或播放状态；
- 根目录不显示无意义的返回按钮。

结论：当前问题对应的操作链路完整闭环。

### 最近播放与收藏

这两个页面与文件夹共用当前的滚动页头，也可能在长列表滚动后丢失返回入口。把其现有返回按钮一并迁移到固定导航栏，可以避免同类问题继续存在。

返回时只执行 `tab = 0`，保留 `folder`。如果用户原先在子文件夹中打开最近播放或收藏，返回后会回到原子文件夹，这与当前行为一致。

结论：闭环且不改变原有状态语义。

### 设置页

设置页继续保留内容区的“返回课程库”按钮和既有设置页手势。顶部固定返回按钮不应在 `tab == 3` 时出现，即使 `folder` 非空。

结论：使用修正后的显示条件时不会重复；若条件写错，会出现双返回入口，但不会永久卡死。

## 状态组合核对

| `tab` | `folder` | 顶部标题 | 顶部返回按钮 | 点击结果 |
| --- | --- | --- | --- | --- |
| 0 | 空 | 雷 player | 不显示 | 无内部返回目标 |
| 0 | 非空 | 当前文件夹名 | 显示 | 返回父文件夹或根目录 |
| 1 | 任意 | 最近播放 | 显示 | `tab = 0`，回到先前课程目录 |
| 2 | 任意 | 我的收藏 | 显示 | `tab = 0`，回到先前课程目录 |
| 3 | 任意 | 保持设置页现状 | 不新增 | 使用设置页原有返回入口 |

标题判断必须优先判断 `tab`，之后才判断 `folder`。否则从子文件夹进入最近播放、收藏或设置时，可能错误显示旧文件夹名称。

## 是否会带来新的操作问题

### 1. 长标题空间缩小

文件夹页面增加左侧按钮后，标题可用宽度变小。当前 `GlassAppBar` 会约束标题，使其不覆盖右侧操作区，但实现时仍应：

- 文件夹名称使用普通 `Text`，不要把用户文件夹名当本地化键处理；
- 设置 `maxLines: 1`；
- 设置 `overflow: TextOverflow.ellipsis`；
- 保留“返回”按钮的无障碍标签。

影响是长名称会省略，不会导致布局溢出或按钮无法点击。

### 2. 顶部操作数量增加

文件夹内顶部同时存在返回、设置和更多三个按钮。以当前 64 像素导航栏和 `GlassAppBar` 的布局规则，标题会被约束在中间剩余空间，不会与按钮重叠。窄屏或大字体下可读字符会减少，但操作入口仍然可用。

### 3. 快速连续点击

返回逻辑是同步状态变更，没有异步动画或原生调用。一次点击只会触发一次回调；连续多次点击会逐级返回，符合目录导航预期。本次不需要新增导航锁。

### 4. 弹窗和更多菜单

本次不新增 `PopScope`、系统返回或页面级手势。弹窗、底部面板和更多菜单继续按现有覆盖层方式处理。用户无法穿过覆盖层直接点击顶部返回按钮，因此不会新增“菜单还开着、底层目录已经切换”的问题。

### 5. 返回后滚动位置

当前滚动视图使用 `PageStorageKey('library/$tab/$folder')`。只要不删除或更换该 Key，返回父目录时会继续使用父目录对应的滚动状态。迁移页头不会要求新增 ScrollController。

注意：发布版本启动后 PageStorage 是新的会话状态，不存在旧页头高度残留；开发期间热重载后如果观察到一次滚动偏移，不应误判为正式版本问题。

## 卡顿评估

### 本次调整本身

不会新增可感知卡顿：

- 只是把已有按钮和标题从滚动树移动到固定导航栏；
- 没有手势逐帧监听；
- 没有页面路由动画；
- 没有异步等待；
- 没有磁盘或原生通道调用；
- 原滚动区控件被移除，整体控件数量基本不变。

### 既有列表计算

切换 `folder` 时，`visible` 会根据全部条目过滤当前目录并排序。数据量特别大时可能产生短帧停顿，但旧返回按钮已经执行完全相同的状态变更，因此它不是本次方案带来的新性能问题。

不建议为返回动作增加加载框、延时或异步任务；这些做法反而会产生按钮点击后等待的卡点。

## 其他状态点是否会卡住

### 导入、扫描、文件操作进行中

返回按钮必须保持可用，不与 `fileBusy`、`scanning` 或 `importing` 绑定。用户返回父目录后，后台操作继续由 `PlayerModel` 管理，不会卡住导航。

### 当前目录被删除或移动

页面可能短暂显示空内容，但 `folder` 仍保留父路径信息，固定按钮仍能向上返回，不会把用户困在失效目录中。

### 当前正在播放

迷你播放/继续学习状态由模型维护，文件夹返回只改变列表筛选范围，不会停止播放，也不会等待播放状态完成。

### 页面进入后台再恢复

本次没有新增手势状态或动画控制器，因此不存在进入后台后手势变量没有清理、按钮失效等新增风险。

## 最终实施边界

为了保持方案简单，后续实现只应包含：

1. 按修正后的状态条件生成 `GlassAppBar.leading`；
2. 按 `tab` 优先、`folder` 次之的顺序生成标题；
3. 复用现有返回回调；
4. 从滚动页头移除已经迁移的返回行；
5. 保留设置页、滚动 Key、导入、播放、菜单和列表逻辑。

不需要增加：

- 文件夹侧滑返回；
- 新的 `PopScope`；
- Navigator 文件夹路由；
- 手势状态；
- 导航锁；
- 加载状态；
- 原生代码修改。

## 手工验收重点

本次未执行自动构建或测试。实施后建议人工检查：

1. 子文件夹滚动到底部后，返回按钮始终可见；
2. 多级目录每次点击只退一级；
3. 子文件夹进入设置页时，设置页不会出现两个返回按钮；
4. 子文件夹进入最近播放/收藏后，标题正确，返回后回到原子文件夹；
5. 长文件夹名和大字体不遮挡设置、更多按钮；
6. 导入、扫描或播放中仍可立即返回；
7. 父目录滚动位置能够恢复；
8. 根目录不显示返回按钮。

## 文件变更记录

- 修改前：最新方案的顶部按钮条件写为 `tab == 1`、`tab == 2` 或 `folder.isNotEmpty`，在“子文件夹 → 设置”组合下会产生重复返回入口。
- 修改后：条件修正为 `tab == 1 || tab == 2 || (tab == 0 && folder.isNotEmpty)`，并新增本次二次独立评估。
- 修改内容：仅修改方案文档和评估文档，未修改业务源码、配置或测试文件。
- 修改原因：验证所有 `tab/folder` 组合并消除设置页重复入口。
- 可能影响：文档层面的实施约束更精确；App 当前运行行为不受影响。
