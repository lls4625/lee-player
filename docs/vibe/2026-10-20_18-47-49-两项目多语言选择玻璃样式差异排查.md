# 雷player与语之初多语言选择玻璃样式差异排查

> 2026-10-20后续决策：先处理雷player课程库根目录、文件夹内容和设置页的滚动卡顿，并增加根目录/文件夹交互滚动条；语言选择器统一延后到性能稳定之后单独实施。完整顺序见 `docs/vibe/2026-10-20_19-12-42-雷player列表滚动性能与滚动条完整优化方案.md`。

## 1. 结论

两张图差异很大，是因为两个项目没有使用同一个组件，也没有使用同一套默认参数：

- 雷player使用锚定在语言输入框附近的 `GlassMenu` + `GlassMenuItem`，所以表现为小型浮动菜单。
- 语之初使用 Material `showModalBottomSheet` 承载 `GlassSheet`，选项行由项目自定义 `StudyListTile` 绘制，所以表现为接近全宽的底部抽屉。
- 雷player锁定 `liquid_glass_widgets 1.3.0`；语之初锁定 `1.4.0`。但两个版本的 `GlassMenu` 和 `GlassSheet` 主要构造默认值基本一致，因此版本差异不是截图差异的首要原因。
- 两边都显式传入了非默认布局或视觉参数，所以严格来说，**两张图都不是“Flutter玻璃组件的唯一默认多语言选择样式”**。
- Flutter SDK本身没有一个名为“默认玻璃多语言选择器”的统一组件。这里使用的是第三方包 `liquid_glass_widgets`，其中 `GlassMenu`、`GlassSheet`、`GlassPicker` 是不同用途的组件，各自有自己的默认样式。

若问题限定为“哪张图更接近 `GlassMenu` 的默认外观”，答案是图1雷player；若限定为“哪张图更接近 `GlassSheet` 的默认外观”，答案是图2语之初。不能跨组件把其中一个称为整个玻璃库的唯一默认样式。

原要求若是“两个项目使用同一种当前玻璃组件及其默认样式”，则当前实现没有满足：两个项目分别选了菜单和底部 Sheet，并进行了不同封装。

## 4. 雷player实际实现

1. `v3/lib/main.dart:17-20` 使用 `GlassThemeData.simple(quality: GlassQuality.standard)`；只固定质量档，没有设置语之初使用的 blur/thickness/tint。
2. `v3/lib/library_page.dart:875-1027` 语言入口直接使用 `GlassMenu`。
3. 该菜单显式设置：
   - `autoAdjustToScreen: true`；
   - `menuAlignment: topRight`；
   - 宽度根据页面约束计算，限制在约 220–300；
   - 高度根据五项语言动态计算；
   - `menuPadding: 12`；
   - 每项高度至少 48；
   - 选中项使用项目金色 `check` 图标。
4. 触发器不是包内默认 `GlassPicker`，而是自定义内容的 `GlassButton.custom`。

因此图1是“经过尺寸、对齐、触发器和选中颜色定制的 GlassMenu”，不是无参数默认控件。不过它的浮动、圆角菜单主体和菜单项形态确实主要来自 `GlassMenu`。

## 5. 语之初实际实现

1. `src/lib/glass_ui.dart:20-26` 使用 `GlassThemeData.simple`，显式设置 `blur: 8`、`thickness: 24` 和 standard/minimal 质量策略。
2. `src/lib/glass_ui.dart:56-67` 又为控件构造项目专用 `LiquidGlassSettings`，暗色 tint 为 `0x66363B40`，亮色 tint 为 `0x55FFFFFF`。
3. `src/lib/glass_ui.dart:496-528` 的 `showGlassBottomSheet` 不是直接使用包推荐的 `GlassSheet.show`，而是先调用 Material `showModalBottomSheet`，并自定义透明背景、阴影、遮罩颜色和动画时长，再在内部实例化 `GlassSheet`。
4. `GlassSheet` 还显式设置 `quality`、项目专用 `settings`、`stretch: 0` 和 `interactionScale: 1`，覆盖了包默认的弹性参数。
5. `src/lib/app.dart:4380-4449` 用自定义 `StudyListTile` 组织标题、五个选项和说明文字；选中状态使用项目自定义圆形/勾选图标。
6. `src/lib/glass_ui.dart:709-770` 表明 `StudyListTile` 是项目自己实现的 Row/Padding/文字体系，并不是包内 `GlassListTile` 的默认布局。

因此图2是“Material Bottom Sheet 路由 + 定制 GlassSheet + 自定义列表行”的组合，不是纯默认 `GlassSheet`。

## 6. 包默认值对比

本机与锁文件匹配的 1.3.0/1.4.0 包源码显示：

- `GlassMenu` 默认宽度 200、圆角 32、菜单项圆角 24、无额外菜单 padding、stretch 0.5、interactionScale 1.02。
- `GlassSheet` 默认顶部圆角 32、外边距水平/垂直各 8、显示拖动指示、允许滚动、stretch 0.5、interactionScale 1.01。
- `GlassPicker` 默认高度 48、水平 padding 16、圆角 10，点击行为由调用方提供；其 `showSheet` helper 使用标准 Cupertino picker，并不是截图1或截图2的这种五行勾选列表。

雷player覆盖了 `GlassMenu` 的宽度、对齐、padding、高度及触发器。语之初覆盖了 `GlassSheet` 的渲染设置、弹性、缩放和外层路由，内部行完全自定义。由此可证明“两边都是纯默认样式”的说法不成立。

## 7. iOS 27官方依据

Apple已经发布可直接参考的 iOS 27 官方设计资料，而不需要凭项目截图主观选择：

- [Apple Design Resources](https://developer.apple.com/design/resources/) 提供 iOS 27 / iPadOS 27 的 Figma 和 Sketch UI Kit，包含 Liquid Glass 更新后的系统组件与状态。
- [Design kits for iOS, iPadOS, and macOS 27 are here](https://developer.apple.com/news/?id=e2lxw9l1) 明确说明 iOS 27 UI Kit 增加了 Liquid Glass 更新、更多组件和状态，并使设计资源命名更贴近代码。
- [Adopting Liquid Glass](https://developer.apple.com/documentation/TechnologyOverviews/adopting-liquid-glass) 说明标准 SwiftUI/UIKit/AppKit 组件会自动取得当前系统的外观与行为；菜单、popover、sheet 和 action sheet 都有系统定义的层级与转场。Apple建议移除自行添加的 sheet/popover 背景，以保持系统一致性。
- [Materials](https://developer.apple.com/design/human-interface-guidelines/materials) 说明 Liquid Glass用于浮在内容上方的控制和导航功能层，不应把大量内容层卡片全部做成玻璃；自定义玻璃应谨慎使用。
- [Menus](https://developer.apple.com/design/human-interface-guidelines/menus) 说明 iOS/iPadOS菜单默认采用列表式 large layout；菜单应使用平台默认交互和合适的点击尺寸。
- [Picker / menu style](https://developer.apple.com/documentation/swiftui/pickerstyle/menu) 说明短选项可考虑 inline，较多选项可使用 menu；Picker的默认风格应由上下文决定，而不是固定一套手绘外观。
- [Get to know the new design system](https://developer.apple.com/videos/play/wwdc2025/356/) 和 [Build a UIKit app with the new design](https://developer.apple.com/videos/play/wwdc2025/284/) 展示了新版 action sheet 从触发控件本身展开、与来源保持空间关系，而不是无条件从屏幕底部出现。iOS 27是在这套系统组件基础上的进一步调整。
- [What’s new in SwiftUI（WWDC26）](https://developer.apple.com/videos/play/wwdc2026/269/) 说明使用标准 SwiftUI组件并以 Xcode 27构建时，会自动获得 iOS 27更新后的 Liquid Glass外观；这也说明“靠近系统样式”的可靠途径是系统组件，而不是复制一组固定 blur/tint参数。

对当前语言设置场景的映射如下：

1. 语言是五个互斥、点击后立即生效的短选项，属于选择控件，不是需要用户完成多步骤任务的页面。
2. 在iPhone紧凑宽度下，优先参考系统 `Picker` 的 menu/inline表达，或由语言设置行锚定展开的 action sheet；弹层应保留与触发项的来源关系。
3. 只有加入搜索、语言预览、额外说明或更多配置，使其成为独立任务时，才更适合使用较大的 modal sheet。
4. 无论采用哪种呈现方式，玻璃只用于弹出的功能层；普通设置行和内容卡片不应为了“玻璃感”重复叠加高成本玻璃效果。

因此，以iOS 27为目标时，截图1的“从设置项附近出现的紧凑选择层”在交互结构上更接近Apple当前的菜单/action sheet方向；但现有 `GlassMenu` 仍是第三方Flutter绘制，不等同于Apple原生系统控件，也不能仅凭外观声明已经符合iOS 27。

## 8. 建议的统一口径

如果目标是两个产品视觉与交互一致，应先明确统一到同一种组件，不能只写“使用默认玻璃样式”。建议需求写成以下形式之一：

1. **统一锚定选择菜单（按iOS 27官方交互方向优先）**：两个项目都使用同版本的菜单/Picker组件，从被点击的语言设置行附近展开；选中项使用单一勾选状态，点击后立即生效并关闭。Flutter实现需要按iOS 27 UI Kit对照圆角、间距、字号、材质和转场，不能只沿用第三方包默认值。
2. **统一底部选择 Sheet**：仅在确认需要标题、说明、搜索或其他任务内容时采用。两个项目都使用同版本 `GlassSheet.show` 或同一封装，并统一标题、选项行、选中图标、说明区域、margin、圆角和动画；不要一个用 `GlassMenu`、另一个用自定义 Material Bottom Sheet。

若当前范围始终只有五个短选项，按Apple最新官方方向，采用锚定菜单/Picker。底部 Sheet在大字号或未来选项显著增加时可作为自适应方案，而不是固定默认方案。该调整不得给滚动设置页增加新的常驻standard玻璃：设置行触发器使用轻量内容样式，只有短时出现的菜单浮层使用standard玻璃。
