# 首次安装主题默认值排查

## 一、结论

当前“首次安装后默认跟随系统”是源码默认值造成的，不是 iOS 主题识别异常。

项目文档声明“首次安装默认使用深色主题”，但实际代码中存在两个仍为 `system` 的缺省值：

1. `v3/lib/player_model.dart`：

```dart
String appearance = 'system';
```

2. `v3/ios/Runner/PlayerBridge.swift`：

```swift
result(UserDefaults.standard.string(forKey: "appearance.mode") ?? "system")
```

因此，真正没有保存过 `appearance.mode` 的首次安装会按 `ThemeMode.system` 显示。若设备当前是浅色外观，雷player首次启动也会显示浅色；设置页同时会选中“跟随系统”。

## 二、当前启动链路

### 1. Flutter 启动时先使用内存默认值

`PlayerModel` 创建时，`appearance` 立即初始化为 `system`。`LeePlayerApp` 在 `runApp` 后读取这个值，并转换为：

```dart
ThemeMode.system
```

因此，应用第一帧已经是跟随系统。

### 2. 偏好稍后异步加载

`LibraryPage.initState()` 才调用：

```dart
unawaited(m.initialize());
```

初始化过程中再通过 MethodChannel 请求原生端的 `appearance`。

### 3. 原生端缺少保存值时仍返回 system

首次安装没有 `appearance.mode`，原生端使用 `?? "system"` 返回跟随系统。于是异步加载完成后，Flutter 仍保持 `system`，不会切换成深色。

## 三、与需求的矛盾

`v3/README.md` 已明确记录：

> 设置页提供跟随系统、浅色、深色外观，选择后立即生效并全局持久保存；首次安装默认使用深色主题。

但该要求没有同步落实到 Dart 初始状态和原生持久化缺省值。`git blame` 显示：

- 原生 `?? "system"` 从初始提交起一直存在；
- Dart 的 `appearance = 'system'` 在后续健壮性修改中仍保留；
- README 从初始版本起就写明默认深色。

所以这是长期存在的“文档/需求与实现不一致”，不是最近真机或系统状态导致的新问题。

## 四、不会覆盖用户选择的正确修复

需要同时修改两处默认值：

### 1. Flutter 内存默认值改为 dark

```dart
String appearance = 'dark';
```

作用：首次启动第一帧直接使用深色，避免先跟随系统、随后再切换深色的闪烁。

### 2. iOS 缺省回退值改为 dark

```swift
result(UserDefaults.standard.string(forKey: "appearance.mode") ?? "dark")
```

作用：仅当 `appearance.mode` 从未保存时返回深色。

### 3. 保留用户已保存的选择

`UserDefaults.standard.string(forKey:)` 在已保存时会返回实际值，因此：

- 用户选择过 `system`：继续返回 `system`；
- 用户选择过 `light`：继续返回 `light`；
- 用户选择过 `dark`：继续返回 `dark`；
- 从未选择、键不存在：返回新的默认值 `dark`。

这不会强制所有现有用户改成深色，也不会覆盖明确选择的“跟随系统”或“浅色”。

## 五、安装方式对结果的影响

需要区分以下场景：

| 操作 | `UserDefaults` 通常是否保留 | 预期结果 |
| --- | --- | --- |
| TestFlight/App Store 更新版本 | 保留 | 延续用户上次选择 |
| Xcode 直接覆盖安装 | 通常保留 | 延续用户上次选择 |
| 删除 App 后重新安装 | 删除 App 数据 | 使用代码缺省值 |
| “卸载 App/Offload App”后重装 | 数据可能保留 | 可能延续上次选择 |

因此，修复后验证“首次安装默认深色”时，需要先确认设备上是删除 App 及其数据后重新安装，而不是仅覆盖安装或使用系统的“卸载 App”。

即使安装方式保留了旧数据，用户明确选择过“跟随系统”后继续跟随系统也是正确行为，不能在每次启动时强制覆盖为深色。

## 六、建议验证范围

源码修改后由用户手动验证：

1. 删除 App 后安装，系统浅色：首次启动应为深色，设置页选中“深色”；
2. 删除 App 后安装，系统深色：首次启动应为深色；
3. 选择“跟随系统”，分别切换系统浅色和深色，App 应跟随；
4. 选择“浅色”，系统深色时 App 仍保持浅色；
5. 选择“深色”，系统浅色时 App 仍保持深色；
6. 选择任一模式后关闭并重新打开 App，选择应保留；
7. 从旧版本覆盖安装，已明确选择的主题不应被重置；
8. 检查系统文件选择器的 `overrideUserInterfaceStyle` 是否与保存后的选择一致。

## 七、预计源码修改范围

后续确认实施时，仅需修改：

- `v3/lib/player_model.dart`：Flutter 启动内存默认值；
- `v3/ios/Runner/PlayerBridge.swift`：不存在已保存偏好时的原生回退值。

建议同步补充与主题默认值有关的既有测试预期，但根据当前项目要求，是否编写或执行测试需由用户另行明确授权。
